# Memory-Native Training: от counter-state к трансформеру как конечному автомату

## 1. Главный вывод

Исходная идея сильнее, чем «тернарный вес плюс счётчик». Это первый порядок **sigma-delta / error-feedback оптимизатора**: видимый вес меняется редко крупными квантами, а скрытое конечное состояние накапливает подпороговые обновления. Из этого получается единый проект, закрывающий четыре независимых источника памяти:

1. параметры — 6-битное состояние синапса;
2. optimizer state — спрятан внутри того же конечного состояния и нескольких row/block-скаляров;
3. градиенты — вычисляются плиткой и тут же поглощаются переходом состояния;
4. активации — восстанавливаются обратимым блоком или пересчитываются по сегментам.

Нельзя получить настоящий выигрыш, исправляя только один из этих четырёх пулов.

---

## 2. Что реально хранит исходный код

Логическая модель одного коэффициента:

- `t ∈ {-1,0,+1}` — видимый тернарный вес;
- `c ∈ {-(C-1),...,C-1}` — остаточный счётчик;
- `s` — масштаб строки;
- `w = s t` — вес forward.

При `C=8` существует `3×15=45` состояний, поэтому информационный минимум равен

```text
ceil(log2 45) = 6 бит.
```

Но в исходном PyTorch-файле `t` и `c` — два FP32-тензора, затем создаются ещё FP32 `w_eff` и полный FP32-градиент. Поэтому в пике counter-слой требует примерно 16 байт на коэффициент, а не 6 бит. Кроме того, подсчёт `model.parameters()` не видит counter-веса, потому что они зарегистрированы как buffers.

Для конфигурации `L=24, d=2048` число counter-коэффициентов:

```text
N = 12 L d² = 1,207,959,552.
```

Отсюда:

| Представление | Память только на counter-коэффициенты |
|---|---:|
| исходные `t+c` FP32 | 9.00 GiB |
| плюс `w_eff+grad` FP32 в пике | ещё 9.00 GiB |
| практический `uint8 state` | 1.125 GiB |
| настоящий packed 6-bit | 0.844 GiB |

Активации в эту таблицу не входят.

## 3. Математика: почему механизм имеет право работать

Пусть масштаб `s` пока фиксирован. Введём целое скрытое состояние

```math
z_k = C t_k + c_k
```

и непрерывный shadow-вес

```math
θ_k = (s/C) z_k = s t_k + (s/C)c_k.
```

Пусть `ĝ_k` — несмещённая оценка градиента, а stochastic rounding также несмещён. Пока тернарная граница не насыщена, carry/remainder арифметика даёт

```math
E[θ_{k+1}-θ_k | F_k] = -η g_k.
```

Одновременно видимый вес `w_k=s t_k` находится от shadow-веса на ограниченном расстоянии:

```math
|θ_k-w_k| ≤ s(C-1)/C < s.
```

То есть конечный автомат отслеживает траекторию обычного SGD с ограниченной ошибкой квантования. На границах `t=±1` это превращается в projected SGD с гистерезисом. Счётчик — не косметический буфер, а error-feedback память, спасающая маленькие обновления от исчезновения.

### Важная поправка при обучаемом масштабе

Счётчик хранит незавершённое обновление величины `r=s c/C`. Поэтому при `s_old → s_new` остаток надо перебазировать:

```math
c ← SR(c · s_old/s_new),
```

а затем добавлять новые ticks. Иначе изменение масштаба самопроизвольно меняет уже накопленную ошибку.

### Все шесть бит можно использовать лучше

При совместном кодировании ограничение имеет вид

```math
3(2C-1) ≤ 64.
```

Максимум — `C=11`, то есть 63 состояния: три видимых значения и 21 скрытая фаза. Это эффективнее жёсткого разбиения «2+4». Ещё более общий вопрос: как оптимально разделить 64 состояния между точностью видимого веса и памятью оптимизатора?

## 4. Fused counter training

Для линейного слоя

```math
Y=XW^T,                 ∇W=Δ^T X.
```

Полный `∇W` не является математически необходимым объектом. Достаточно:

1. сформировать одну плитку `∇W[I,J]` в FP32-регистрах;
2. прочитать 6/8-битные состояния этой плитки;
3. применить stochastic transition;
4. записать новые состояния;
5. уничтожить плитку градиента.

Следствие: квантовать градиент ради памяти уже не обязательно — он никогда не попадает в HBM. Прямая stochastic-rounding конверсия градиента в counter ticks имеет меньшую дисперсию. Тернарный gradient-pulse остаётся полезным как вариант для коммуникации и аппаратно событийного режима.

Практический kernel:

```text
FP32 accumulator tile
        ↓
row/block statistics
        ↓
gradient symbol or direct tick
        ↓
state = LUT[state, symbol, layer_class]
        ↓
write 6/8-bit state only
```

Для устойчивости вместо per-weight Adam достаточно проверить row/block RMS:

```math
v_i ← βv_i + (1-β) mean_j(g_{ij}²),
```

что требует `O(out_features)`, а не `O(out_features·in_features)` памяти.

Weight decay естественно применять к shadow-state:

```math
z ← SR((1-ηλ)z - η C ĝ/s),
```

а не пытаться отдельно «декрементировать» тернарный вес.

## 5. Следующий шаг: 64-state synapse вместо ручного счётчика

Пусть каждый коэффициент хранит ровно

```text
q_ij ∈ {0,...,63}.
```

Есть два общих объекта:

```math
w_{ij}=s_i D(q_{ij}),
q'_{ij}=T(q_{ij}, b(g_{ij}), layer_type, phase, ξ).
```

- `D` — decoder видимого веса;
- `b(g)` — 3–5-битный символ нормализованного градиента;
- `T` — маленькая shared transition table;
- `ξ` — counter-based random bit для несмещённых переходов.

Разные состояния могут иметь одинаковый `D(q)`, но различную скрытую динамику. Именно так в шести битах одновременно живут вес, остаток, знак momentum и «возраст» устойчивого градиента.

### Как найти таблицу, а не придумать её вручную

Лучший путь — **distillation непрерывного оптимизатора в конечный автомат**:

1. обучить маленькую teacher-модель AdamW/ECO;
2. записать нормализованные последовательности `(g,w,m,v)`;
3. выучить 64-state Markov transducer, минимизирующий loss-sensitive ошибку траектории;
4. наложить симметрию знака, отсутствие дрейфа при `g=0`, ограниченный jump и bounded-error условие;
5. затвердить вероятностную модель в LUT;
6. проверить уже end-to-end.

Это задача rate-distortion и управления, а не только нейросетевая эвристика. Можно оптимизировать таблицу динамическим программированием на квадратичной локальной модели loss либо softmax-релаксацией и meta-gradient.

### Bit-budget annealing

Одни и те же 64 кода можно декодировать по-разному в ходе обучения:

- начало: 16 видимых уровней × 4 скрытые фазы;
- середина: 8 уровней × 8 фаз;
- конец: 3 уровня × 21 фазу.

В начале важнее широкий диапазон крупных шагов, в конце — накопление микроскопических обновлений. Переход между кодировками делается редким re-encode проходом, сохраняющим shadow-вес.

## 6. Минимально-памятный трансформер

### Слой 1 — finite-state параметры

- 6-bit packed state либо быстрый uint8;
- FP16/FP32 scale на строку или блок;
- row-RMS/row-momentum, если нужны, `O(d)`;
- embedding и normalization в BF16/FP16;
- tied input/output embedding.

### Слой 2 — gradient streaming

- tiled GEMM backward;
- update внутри epilogue;
- ни полного градиента, ни master weight, ни `m,v` на каждый коэффициент;
- commit только после вычисления `grad_x` старым весом.

### Слой 3 — reversible activation path

Разделить hidden-state на две части:

```math
y_1=x_1+F(x_2),

y_2=x_2+G(y_1).
```

Обратный ход:

```math
x_2=y_2-G(y_1),

x_1=y_1-F(x_2).
```

Хранятся выход блока, RNG seed и малая correction information; внутренние активации пересчитываются. В конечной точности нужен integer/fixed-point coupling либо редкие anchor-активации, иначе обратное восстановление накапливает округление.

Важна транзакционная семантика: блок сначала полностью восстанавливается и вычисляет `grad_x`, только затем его finite-state веса commit-ятся. Иначе recompute увидит уже новые веса.

### Слой 4 — attention memory

- Flash-style attention убирает `T²`-матрицу;
- local sliding attention обрабатывает точные близкие зависимости;
- recurrent/SSM memory несёт дальний контекст;
- sparse episodic store сохраняет только «удивительные» события.

Это не нарушает информационную границу: модель с постоянным состоянием не может гарантированно помнить произвольную последовательность длины `T`; она обязана сжимать, выбирать или обращаться к внешней памяти.

## 7. Новая архитектура: Reversible Finite-State Operator Network

Базовый блок:

```math
a' = a + F_local-attn/SSM(b; Q_F),

b' = b + G_structured(a'; Q_G).
```

`Q_F,Q_G` — массивы 6-битных синаптических состояний. Внутри `F,G` плотные матрицы постепенно заменяются операторами

```math
W x = Σ_r D_{r,0} H P_{r,1} D_{r,1} H ... x + U V^T x,
```

где:

- `H` — фиксированный Hadamard/FFT-подобный transform;
- `P` — фиксированная permutation;
- `D` — обучаемые finite-state диагонали/малые блоки;
- `UVᵀ` — небольшой low-rank escape channel.

Это снижает не только байты на коэффициент, но и само число коэффициентов с `O(d²)` до примерно `O(kd+rd)`. Однако таким слоям нужны собственные initialization и learning-rate laws; их нельзя честно оценивать с гиперпараметрами плотного слоя.

## 8. Фундаментальные пределы

1. Произвольная независимая тернарная матрица из `N` элементов требует не меньше `N log₂3 ≈ 1.585N` бит. Ни упаковка, ни kernel не перейдут эту границу без структуры.
2. Точный reverse-mode обязан либо хранить потерянную информацию, либо пересчитывать её, либо делать преобразование обратимым. «Нулевая память и нулевой recompute» невозможны для произвольной необратимой сети.
3. Независимый Adam-state для каждого веса требует `Ω(N)` памяти. Для радикального сокращения надо менять сам optimizer-state: finite-state, factorized или shared.
4. Точное хранение `T` произвольных токенов алфавита `V` требует порядка `T log₂V` бит где-либо — в KV, recurrent state или внешней памяти.
5. Минимум памяти не равен максимуму скорости: плохая 6-битная распаковка может проиграть хорошо оптимизированному INT8. Цель — минимум HBM traffic при высокой tensor-core occupancy.

## 9. Что уже проверено в рабочем прототипе

`counter_state_fused_v2.py` реализует:

- одно `uint8` состояние на weight;
- отсутствие FP master и per-weight moments;
- tile-wise update внутри backward;
- отсутствие полного weight-gradient buffer;
- корректный учёт buffers;
- tied embedding/head;
- обучаемый periodic toy corpus;
- rebasing счётчика при изменении scale.

Проверки на CPU:

```text
micro GPT, periodic next-token:
loss 3.4841 → 0.1372 за 200 шагов.
```

Отдельный 16×16 linear teacher с фиксированной скрытой тернарной матрицей:

```text
MSE 1.160895 → 0.000000,
совпадение тернарной матрицы = 100%.
```

Это доказывает работоспособность механизма обновления, но ещё не доказывает parity на естественном языке.

Предварительная 5-seed абляция на teacher-задаче показала преимущество использования всех состояний:

| C | состояний | лучший mean final MSE среди двух pulse modes |
|---:|---:|---:|
| 4 | 21 | ~0.0116 |
| 8 | 45 | ~0.0021–0.0031 |
| 11 | 63 | ~0.00081–0.00148 |

Это небольшой синтетический тест, а не финальный вывод.

## 10. Жёсткая лестница экспериментов

### A. Математическая верификация

- unbiased drift shadow-weight;
- bounded tracking error;
- scale-rebase invariant;
- saturated boundary behavior;
- finite-state weight decay;
- state entropy и фактическое число используемых бит.

### B. 10–30M language model

Одинаковые данные, tokenizer, tokens и compute budget:

1. BF16 AdamW;
2. ternary/BitNet-style QAT с master weights;
3. finite-state `C=4,8,11`;
4. direct ticks против ternary pulses;
5. ручной counter против learned 64-state LUT;
6. row-RMS on/off.

Метрики: validation nats/token, peak allocated/reserved memory, bytes moved, tokens/s, flip rate, saturation, counter entropy, shadow drift.

### C. Kernel

Сначала быстрый uint8 kernel. Только после parity — packed 6-bit `4 states / 3 bytes`. Иначе можно потратить месяцы на упаковку слабой динамики.

### D. Activation pass

- checkpointed blocks;
- reversible coupling;
- exact/fixed-point correction bits;
- atomic recompute-update scheduler.

### E. Architecture pass

Только после устойчивого dense finite-state baseline:

- local attention + invertible SSM;
- Hadamard/Monarch/BTT-like structured operators;
- low-rank escape branch;
- sparse episodic memory.

### F. Scaling law gate

Масштабы примерно 10M → 30M → 100M. Переход к 1B только если loss-gap не растёт с размером и реальный kernel даёт ожидаемый memory/throughput выигрыш.

## 11. Наиболее перспективная гипотеза

Самая сильная версия проекта — не «тернарный Transformer без Adam», а:

> **Сеть, где каждый синапс является 64-состояниевым обучаемым автоматом, каждый блок обратим, каждый градиент существует только в регистрах, а плотная матрица постепенно заменяется композицией малых структурированных операторов.**

Это уже архитектура, рожденная для малой памяти, а не обычный Transformer, сжатый после рождения.
